# ALAS-Android 模块映射

> 本文档列出 **ALAS（Python）→ ALAS-Android（Kotlin）** 与 **MAA（Android 方案）→ 本项目** 的模块/概念映射，均基于仓库实际源码（包名 `com.alas.android`）。

---

## 2. MAA（Android 方案）→ 本项目

| MAA 概念 | 本项目对应 | 说明 |
| --- | --- | --- |
| MaaTouch app / MAA GUI | `ui/MainActivity.kt` | Compose 主界面、启动/停止、MediaProjection 授权 |
| 调度守护 / 前台服务 | `service/AlasForegroundService.kt` | 前台服务保活，`START_STICKY`，状态通知 |
| MediaProjection 截图授权持有 | `service/ScreenCaptureService.kt` | 持 `MediaProjection`，`getProjection()` / `buildIntent()` |
| 无障碍输入通道 | `service/AlasAccessibilityService.kt` + `AccessibilityInput` | `dispatchGesture` 注入 |
| 原生控制单元 `MaaAndroidNativeControlUnit`（本地截图 + 触控注入） | `MediaProjectionScreencap` + `NativeInput` / `AccessibilityInput` | 设备端自控 |
| `ControllerAPI`（screencap + input） | `DeviceController`、`Screencap`、`Input` | 统一设备动作抽象 |
| `MaaTouch` `Controller.java`（反射 `injectInputEvent`） | `NativeInput` + `PointersState` | 原生注入 MotionEvent/KeyEvent |
| 无障碍 `dispatchGesture` 方案 | `AccessibilityInput` | 免 root 备选输入 |
| `InputManager.injectInputEvent` 的 ADB 等价（`AdbInput`） | `AdbShellInput` / `MinitouchInput` | 外控输入 |
| ADB screencap | `AdbScreencap` + `AdbRunner` | 外控截图 |
| Vision / Pipeline 节点识别 | `core/vision`（`TemplateImage`/`Button`/`ImageUtils`）+ 调度器 | 识别能力 + `Scheduler` 调度节点执行 |

## 3. 关键映射要点

- **中央控制权**：MAA 的 `ControllerAPI`（controller + resource + task）对应本项目的"设备控制层 + 识别层 + 调度层"；`DeviceController` 是设备动作的门面，`Scheduler` 是任务执行的门面。
- **输入抽象统一**：无论自控还是外控，上层玩法只面对 `Input` 接口的 `click/swipe/longClick/keyEvent/inputText/touchDown/Move/Up`，实现可替换（ADB shell / minitouch / native / accessibility），由 `Runtime` 按 `device_mode` + `input_method` 决定。
- **截图抽象统一**：`Screencap.capture()` 对外只返回 `Screenshot`；自控用 `MediaProjectionScreencap`，外控用 `AdbScreencap`，识别层无感知。
- **调度语义**：`Scheduler`（对应 ALAS `alas.py`）与 `TaskConfig`（对应 ALAS 配置节点 / MAA Pipeline 的调度信息）一起实现"到期 → 取优先级最高 → 执行 → 写回 NextRun → 失败计数 → 人工接管"。
- **模块化扩展**：新增玩法只需实现 `Task` 接口（继承 `ModuleBase`），并在 `Runtime.start` 的 `tasks` 映射中注册，即可被调度器驱动。
