# ALAS-Android 构建与部署

> 本文档基于仓库内实际构建脚本（`build.gradle.kts`、`settings.gradle.kts`、`gradle.properties`、`AndroidManifest.xml`）与源码编写。

**重要前提**：当前编写/维护本文档的环境（本仓库所在沙箱）**没有安装 Android 工具链**（无 JDK、无 Android SDK、无 Gradle wrapper），因此仓库代码 **尚未在本环境编译过**。本文档给出的构建命令与版本要求依据项目构建配置整理，实际执行前请按第 1 节补齐环境。

## 2. 构建步骤

### 2.1 准备

1. 安装 Android Studio（含 JDK 17），并在 SDK Manager 中安装 **Android SDK Platform 34**。
2. 配置 `local.properties`（含 `sdk.dir`）或通过环境变量 `ANDROID_HOME`/`ANDROID_SDK_ROOT` 指定 SDK 路径。`local.properties` 已被 `.gitignore` 忽略，不会入库。
3. 因仓库未含 Gradle wrapper，请二选一：
   - 在 Android Studio 中打开工程自动生成 wrapper；或
   - 用本机 Gradle（8.9+）直接执行下面的任务。

### 2.2 调试包

```bash
./gradlew assembleDebug
# 或未用 wrapper 时：
gradle assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。Debug 包便于 `adb install` 与调试。

### 2.3 发布包

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`。

`app/build.gradle.kts` 中 `release` 构建类型当前为 `isMinifyEnabled = false`（未开启混淆压缩），但已配置：

- `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`；
- `app/proguard-rules.pro` 保留了 OpenCV Java 绑定与反射调用的输入包：
  ```
  -keep class org.opencv.** { *; }
  -keep class org.opencv.engine.** { *; }
  -keep class com.alas.android.core.device.input.** { *; }   # NativeInput 反射
  ```
- `packaging.jniLibs { useLegacyPackaging = true }`：OpenCV 自带多架构 `.so`，按需剔除可避免包体膨胀。

### 2.4 安装到设备

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 3. 运行模式配置

应用启动后，`MainActivity` 显示"连接模式：ADB / 无线调试 / 设备端自控"。运行模式由 `config.json`（运行时持久化到应用 `files/config.json`，源码内置示例见 `app/src/main/assets/config.json`）决定：

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `server` | `cn` / `en` / `jp` / `tw` | 服务器区服，决定模板目录 `templates/<server>/` |
| `device_mode` | `adb` / `self_control` | 连接模式：ADB(含无线调试) / 设备端自控 |
| `adb_address` | 如 `127.0.0.1:5555` | ADB 目标地址（`-s <serial>`） |
| `input_method` | `adb_shell` / `minitouch` | ADB 模式的输入实现（`native`/`accessibility` 枚举存在，但仅自控模式使用） |

> 默认内置 `config.json`：`server=cn`、`device_mode=adb`、`adb_address=127.0.0.1:5555`、`input_method=adb_shell`。

### 3.1 设备端自控（SELF_CONTROL）

免电脑运行：手机本地 MediaProjection 截屏 + 原生/无障碍输入。

**步骤：**

1. 将 `config.json` 的 `device_mode` 设为 `self_control`（首次运行会自动生成默认配置，需手动改）。
2. **开启无障碍服务**（可选输入通道，推荐）：
   - 系统设置 → 无障碍 → 无障碍已下载的应用 → 找到"**ALAS 无障碍服务**"并开启（服务声明见 `AndroidManifest.xml` 的 `AlasAccessibilityService`，配置见 `res/xml/accessibility_service_config.xml`，已开启 `canPerformGestures="true"` 手势注入能力）。
   - 开启后，`Runtime.buildSelfControl` 会优先构造 `AccessibilityInput(accessibilityService)` 通过 `dispatchGesture` 注入手势（免 root、免系统签名）。
   - 若不开无障碍，则回退到 `NativeInput()`（反射 `InputManager.injectInputEvent`，需要 **root 或系统签名**，见第 5 节注意事项）。
3. **授予屏幕录制（MediaProjection）权限**：
   - 在应用主界面点击"**启动自动化**"。
   - `MainActivity.requestProjection()` 调用 `MediaProjectionManager.createScreenCaptureIntent()`，系统会弹出"开始投屏/录制"授权对话框，选择允许。
   - 授权返回后，`ScreenCaptureService` 以前台服务持有授权结果，`Runtime.start(this, projectionHolder=…)` 启动设备端自控。
4. 应用会再启动 `AlasForegroundService`（前台守护服务，通知"ALAS 自动化运行中"）保持调度常驻。

### 3.2 ADB 控制（USB / 外控）

通过电脑控制真机或模拟器。

**步骤：**

1. 手机开启**开发者选项 → USB 调试**，用 USB 连接电脑；`adb devices` 确认设备在线。
2. 将 `config.json` 的 `device_mode` 设为 `adb`，`adb_address` 设为 `127.0.0.1:5555`（模拟器本机）或留空（使用系统中唯一设备，`AdbRunner.serial=null`）。
3. 选择 `input_method`：默认 `adb_shell`（`adb shell input`，兼容最高、速度较慢）；若设备已装 minitouch，可改 `minitouch`（本地 socket，更快）。
4. 在主界面点"启动自动化"，`Runtime.buildAdb` 构造 `AdbRunner` + `AdbScreencap` + 输入实现并启动调度。

### 3.3 无线调试

通过网络连接（无需 USB 线），适合自控/外控两用。

**方式 A：传统无线 ADB（Android 11 以下或已 root）**

```bash
# 手机 USB 连接电脑后：
adb tcpip 5555                # 让设备在 5555 端口开启 adbd
adb connect <手机IP>:5555     # 如 192.168.1.10:5555
adb devices                   # 确认无线设备在线
```

然后把 `config.json` 的 `adb_address` 设为该无线地址（如 `192.168.1.10:5555`），`device_mode=adb`，启动即可。

**方式 B：Android 11+ 无线调试（配对）**

1. 手机 **开发者选项 → 无线调试** → 开启。
2. 点击"使用配对码配对设备"，界面显示 `ip:port` 与 6 位配对码。
3. 电脑执行：
   ```bash
   adb pair <ip:port>          # 输入配对码
   adb connect <ip:port>       # 连接
   adb devices                 # 确认在线
   ```
4. 将 `adb_address` 设为该连接地址后启动。

> `AdbRunner` 代码中已提供 `connect(address)` / `disconnect(address)`（对应 `adb connect/disconnect`），供运行时/上层发起无线连接。

## 4. 模板资源放置

识别依赖的 PNG 模板放在 `app/src/main/assets/templates/`，目录结构对齐 ALAS 的 `assets/<server>/<category>/`：

```
app/src/main/assets/templates/
├─ cn/                     # 服务器：cn / en / jp / tw
│  ├─ handler/             # 通用弹窗(登录/公告/信息栏/掉落实体)
│  │  ├─ LOGIN_ANNOUNCE.png
│  │  ├─ LOGIN_CHECK.png
│  │  ├─ MAIN_MENU.png
│  │  ├─ INFO_BAR_1.png
│  │  └─ GET_ITEMS_SHIP_1.png
│  ├─ commission/          # 委托
│  │  ├─ HARVEST_ALL.png
│  │  └─ DISPATCH.png
│  ├─ research/            # 科研
│  │  └─ START_RESEARCH.png
│  ├─ reward/              # 奖励收获
│  │  └─ CLAIM.png
│  └─ daily/               # 每日
│     └─ CLAIM.png
├─ en/
├─ jp/
└─ tw/
```

**模板规格**（对齐 `assets/templates/README.md`）：

- 格式：**PNG**，尺寸以游戏内实际截取元素为准（建议 720p 下截取）。
- 命名：**大写**，与代码中 `template("<category>/<NAME>.png")` 一致（`TemplateImage.fromAssets` 会把文件名大写化）。
- 分辨率：识别坐标系固定为 **1280×720**（对齐 ALAS），`AdbScreencap.orientAndScale` 会自动校正旋转与缩放。
- 加载优先级：用户扩展目录 `files/templates/<path>` → assets 内置 `templates/<path>`（见 `ResourceManager.load`），可用扩展目录免重装更新模板。

**坐标校准（重要）**：当前各玩法（`CommissionTask` / `ResearchTask` / `DailyTask` / `RewardTask` / `LoginHandler`）中的按钮坐标为**示意占位**（如 `Point(640, 600)`、`Roi(0, 0, 1280, 720)`），真实使用时必须对照你的设备分辨率与游戏 UI 重新校准，并用模板匹配命中点替代硬编码坐标。

## 5. 已知构建/运行注意事项

1. **OpenCV 依赖**：识别层依赖 `org.opencv:opencv:4.9.0`。`AlasApplication.initOpenCV()` 使用 `OpenCVLoader.initLocal()` 本地初始化；若本地初始化失败，代码留了"回退到 OpenCVManager 下载方案"的注释（需自行实现）。打包时多架构 `.so` 可能导致包体较大，已设 `useLegacyPackaging`，可按设备架构剔除无用 ABI。
2. **NativeInput 反射**：`NativeInput` 通过反射调用系统隐藏 API `InputManager.injectInputEvent`（`INJECT_MODE_ASYNC`），**需要系统签名 / root 权限**；若拿不到会抛 `IllegalStateException`。普通安装（非系统签名、无 root）的设备应改用 `AccessibilityInput`（无障碍 `dispatchGesture`）。为此 `proguard-rules.pro` 保留了 `core.device.input` 包，避免混淆破坏反射。
3. **无障碍需手动开启**：无障碍服务必须在系统设置中手动开启才可用；未开启时自控模式回退 `NativeInput`（需高权限）。
4. **MediaProjection 每次授权一次性**：`ScreenCaptureService` 在 `onDestroy` 会 `projection?.stop()`，MediaProjection 授权在本次运行会话内有效，重启自动化需重新授权。
5. **任务注册与默认配置需对齐**：`Runtime.start` 的 `tasks` 映射已注册 `commission/research/daily/reward` 四个玩法；若你在 `config.json` 启用了其他 `command`（如 `restart`），需在 `tasks` 映射中补注册对应 `Task`，否则调度器会报"no task implementation"并按失败处理。
6. **ADB 分支输入选择**：`Runtime.buildAdb` 目前只映射 `minitouch` 与 `adb_shell`；`input_method` 设为 `native`/`accessibility` 时仍走 `adb_shell`（仅 `InputKind` 枚举存在）。
7. **无 Gradle wrapper / 未编译状态**：仓库未附带 `gradlew` 与 `gradle/wrapper`；且本维护环境无 Android 工具链，源码尚未在本环境编译验证。首次构建请先生成 wrapper 或使用本机 Gradle，并处理可能存在的编译告警/错误。
